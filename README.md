# 校园一卡通（终端版）

一个**纯 C 语言**实现的校园一卡通系统：消费、机房上机计费、门禁考勤、
卡务办理与统计报表。全部为命令行界面，无图形界面、无网页、无网络依赖。

## 运行

双击 **`运行.bat`**（未编译时会自动先构建），或直接运行：

```
main.exe
```

## 构建

双击 **`构建.bat`**，或运行：

```
build.exe             构建 + 跑单元测试
build.exe --test      只跑单元测试
build.exe --clean     删除构建产物
```

手工编译（注意 **必须带 `-fexec-charset=UTF-8`**，否则中文会乱码）：

```bash
gcc -std=c11 -Wall -Wextra -O2 -fexec-charset=UTF-8 main.c campus.c -o main.exe
```

`build.exe` 已随仓库提供；需要自己重编构建器时：

```bash
gcc -std=c11 -O2 build.c -o build.exe
```

## 数据文件

全部为 `|` 分隔的文本，保存在 `data/`：

| 文件 | 内容 | 写入方式 |
|---|---|---|
| `cards.dat` | 全部卡片 | 全量覆写 |
| `ledger.dat` | 交易流水 | 追加 |
| `access.dat` | 门禁记录 | 追加 |
| `<卡号>.txt` | 该卡上机记录 | 追加 |
| `income.dat` | 旧版收入流水（兼容） | 追加 |

字段顺序（`cards.dat`）：
`卡号|姓名|学号|登录密码|交易密码|累计充值|余额|状态|上机|开始时间|地点|日限额|今日已用|日期|单笔限额|有效期`

状态编号 `0 正常 / 1 挂失 / 2 冻结 / 3 已过期`；
交易类型 `0 充值 / 1 消费 / 2 退款 / 3 工本费 / 4 补助`。

## 三个必须记住的坑

这三个都是本项目实际踩过的，源码注释里也有记录。

### 1. 固定长度缓冲区存中文**不能按字节截断**

一个汉字占 3 字节（UTF-8）。按字节数硬砍会在末尾留下不完整的字节序列，
产生非法 UTF-8。曾出现两次：

- `campus_register` 的姓名字段只有 12 字节（只够 4 个汉字）
- 边界回退逻辑写成了无条件执行，把**已经完整**的最后一个汉字也删了

现在统一为：**仅当确实被截断时**才回退到字符边界
（`campus_utf8_trim` / `copy_trim`），由 `test_jstr.c` 守着。

### 2. 终端的中文要同时管好**输入**与**输出**编码

只设 `SetConsoleOutputCP(65001)` 是不够的：控制台默认**输入**代码页是
GBK(936)，那样光标下敲的中文以 GBK 字节进入缓冲区，与内部统一使用的
UTF-8 冲突，存盘后读出来就是乱码。

现在 `main()` 同时设 `SetConsoleCP` 与 `SetConsoleOutputCP`；
另外 `ask_text()` 里还有一层兜底：若拿到的字节不是合法 UTF-8
（例如管道/重定向给的是 GBK），自动按系统 ANSI 代码页转成 UTF-8。

配套的一条经验：**输入缓冲区要比目标字段大**。若两者正好相等，
`fgets` 读满时会把多字节汉字砍断。例如姓名字段 24 字节，
输入缓冲就给 64 字节，让截断发生在有边界保护的拷贝环节。

### 3. 批处理文件必须 GBK + CRLF

`cmd` 按系统 ANSI 代码页读取批处理文件：

- 存成 UTF-8 → 中文注释解析失败
- 行尾为 LF → `rem` 注释行被截断，残句被当成命令执行

所以 `运行.bat` / `构建.bat` 均以 **GBK 保存、CRLF 换行**。

## 已知限制

- 卡片上限 `CARD_MAX` 是编译期常量（默认 200）。超出部分不载入，
  但会显式告警（`cardTruncated`），不静默丢弃。
- 密码以明文写在 `data/cards.dat` 中，仅适合教学演示。
